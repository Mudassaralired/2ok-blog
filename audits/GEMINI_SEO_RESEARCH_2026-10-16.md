## A. 2026 on-page SEO best practices (home decor & DIY)

**Length & structure**
- Google rewards information density, not raw word count. Targets: listicles/inspiration 1,200–1,800 words; DIY tutorials 1,000–2,200 words (scale with complexity). No thin 300-word galleries.
- One H1 per page (matches primary keyword); H2s for sections; H3s for steps. Never style-driven heading levels.
- Anti-fluff intros: 60–120 words max. Para 1 = show finished result (hero photo at/below intro). Para 2 = state the problem solved. Long personal backstories penalised by helpful-content systems.
- **Key Takeaways box (HIGH value 2026)** — prime feeder for Google AI Overviews. 3–4 bullets right after intro with hard numbers (Total Cost: $64 | Active Time: 2 hrs).
- Table of Contents: moderate–high value; compact inline ToC with anchor links; Google uses anchors for SERP jump-links.
- FAQ: 3–5 hyper-specific troubleshooting Qs at bottom (topical completeness; no rich-result dropdowns for decor).

**E-E-A-T**
- Decor is NOT strict YMYL, except DIY with electrical/wiring/building-code (cite pros there).
- First-hand experience non-negotiable: original process + "imperfection" shots; granular data (exact paint names/sheen, real costs); "6-Month Durability Update" boxes.
- Trust pages for AdSense: author bio box on every post → dedicated author archive (/author/name/); About (story, philosophy, testing standards); Contact (working form + domain email + address); footer links to Privacy, Terms, FTC Affiliate Disclosure.
- External links: dofollow to manufacturer tech sheets; rel="sponsored"/"nofollow sponsored" on ALL affiliate links. Person schema: name, jobTitle, knowsAbout, sameAs (Pinterest/Instagram/YouTube/LTK).

**Internal linking**
- Hub-and-spoke per cluster: 1 pillar hub + 6–10 spokes. Hub links to all spokes; spokes link back + 2–3 laterally. Don't scatter random posts across 10 rooms at launch.
- 4–8 contextual internal links per 1,500-word article; 1–2 in upper third.
- Anchor text: 3–6 descriptive words, varied per destination, never "click here".
- Zero-orphan rule: every post needs ≥3 incoming contextual body links. 4–6 core categories as mini-hubs; index/follow categories; noindex tag archives.

**Image SEO**
- AVIF primary (~95%+ support 2026, 20–30% smaller than WebP); WebP fallback via <picture> or CDN (Cloudflare Polish).
- Hero 16:9 (1600×900 or 1200×675), min 1200px wide + max-image-preview:large (Discover cards). In-content verticals 4:5 or 3:4 (Pinterest-savable).
- Budgets: hero 80–100KB; in-content 40–75KB each.
- Hero/LCP: NEVER lazy-load; fetchpriority="high" + loading="eager" + explicit width/height. Below fold: loading="lazy" + decoding="async"; ≥4 srcset breakpoints.
- Descriptive filenames; alt 10–15 words; alt="" for decorative. <image:image> tags in sitemap.

**Schema (beyond BlogPosting)**
- HowTo: DEPRECATED for rich results (retired Sep 2023) — keep lightweight markup only (supply/tool/totalTime/estimatedCost/step) for AI Overviews/LLM parsing.
- FAQPage: restricted rich results (gov/health) — optional.
- **ItemList: ACTIVE, high priority for listicles** (carousels + AI lists); nest ListItem per numbered H2.
- ImageObject: ACTIVE — creator/creditText/copyrightNotice/license (original-photo signal, Lens attribution).
- BreadcrumbList: ACTIVE — clean mobile SERP paths.
- VideoObject: ACTIVE — even 45s transformation clips (name/description/thumbnailUrl/uploadDate).
- Person + Organisation: ACTIVE — BlogPosting → author(Person) + publisher(Org); Knowledge Graph/E-E-A-T signal.
- Single JSON-LD @graph with connected nodes, not isolated blocks.

**Core Web Vitals 2026**
- Good: LCP ≤ 2.5s; INP ≤ 200ms; CLS ≤ 0.1. Decor-blog culprits: uncompressed hero (LCP), social widgets/popups (INP), missing dims + late fonts + unreserved ad slots (CLS).
- Content beats speed as tie-breaker; CWV gates Discover eligibility. Budget INP headroom for Mediavine Journey scripts.

## C. Next.js static export on Cloudflare Pages — SEO pitfalls

1. **Crawlability:** output:'export' only builds paths from generateStaticParams. Set `dynamicParams = false` on dynamic routes so missing slugs 404 loudly in dev.
2. **Trailing slash = #1 duplicate-content trap.** Lock ONE convention identically in next.config, metadataBase, canonicals, sitemap.ts, all <Link> hrefs — else Cloudflare 308s every crawl.
3. Links: Next <Link> → plain <a> in static HTML (crawlable). NEVER router.push on <div>/<button> cards (Googlebot won't discover URLs). Test with JS disabled.
4. **404s:** app/not-found.tsx → /out/404.html served with true HTTP 404. Without it: SPA fallback risk = mass soft-404s.
5. **Sitemap/robots:** native app/sitemap.ts + app/robots.ts work with output:'export'. Add <image:image> entries for step photos. Update lastModified only on real changes. Don't block /_next/static/ in robots. Submit to Search Console + Bing Webmaster Tools.
6. **Metadata:** every post needs full <head> at build time. Set metadataBase (else relative/localhost URLs); add max-image-preview:large; absolute canonicals; skip hreflang on English-only.
7. **Images:** next/image needs unoptimized:true for export — but never ship raw huge files. Options: (a) next-image-export-optimizer (build-time AVIF/WebP breakpoints; watch Cloudflare build limits past ~300 image-heavy posts — pre-optimise locally), (b) Cloudflare /cdn-cgi/image/ loader (free ≤5,000 transformations/mo).
8. **Hero/LCP:** priority/fetchPriority high, eager, never lazy; no CSS fade-in animations on hero. In-content: lazy + async + explicit dims.
9. **Fonts:** next/font self-hosts woff2 — fine with export. display:'swap' + adjustFontFallback.
10. **Hydration bloat:** ~85–100KB gzipped React runtime. Keep article templates/layouts/ToC/bios 100% server components; "use client" only on tiny leaves (mobile menu, copy button). Never "use client" on article wrappers.
11. **DANGER — pages.dev duplicate:** every push deploys to BOTH yourdomain.com AND *.pages.dev (+ branch previews) → Googlebot may index the clone, splitting authority. Fix: `X-Robots-Tag: noindex` on *.pages.dev via public/_headers + Cloudflare Bulk Redirect 301 *.pages.dev → custom domain.
12. **DANGER — edge caching HTML:** never "Cache Everything" with multi-day TTL on HTML (stale content to Googlebot). Granular _headers: short TTL HTML, long immutable for hashed assets + security headers.
13. **_redirects** for slug changes; Bulk Redirects for www/non-www.
14. **ads.txt:** public/ads.txt → /out/ads.txt. On Mediavine Journey: their hosted redirect or paste dynamic lines.
15. **Flat DOM for Mediavine:** Journey injects ads between direct-child <p>/<h2>/<figure> inside .entry-content. Don't nest paragraphs in div wrappers.
16. **AdSense verification:** verification <script> must be in RAW static HTML <head> (bots may not hydrate) — root layout <head>, strategy afterInteractive/lazyOnload for the rest.

## Master do/don't (pre-launch)
- DO lock trailingSlash everywhere; DON'T mix /slug and /slug/.
- DO native <a>/<Link> in static HTML, test JS-disabled; DON'T router.push cards or infinite scroll without paginated URLs.
- DO pre-generate AVIF/WebP + srcset, hero fetchpriority high; DON'T serve raw 2MB JPEGs or lazy-load hero.
- DO noindex *.pages.dev via _headers; DON'T leave the clone crawlable.
- DO flat <p>/<h2>/<figure> siblings in .entry-content; DON'T nest in divs or "use client" templates.
- DO max-image-preview:large + 1200px+ absolute og:images; DON'T leave metadataBase unset.
